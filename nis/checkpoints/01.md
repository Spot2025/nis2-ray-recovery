## Краткий итог

Выбран рабочий вариант приложения: синхронное обучение небольшой ConvNet
на MNIST с parameter server. Готовый Ray используется как runtime;
собственная часть — состояние нескольких акторов, восстановление,
процессный baseline, управление отказами и проверка результатов.

Назначенный Ray `2ff4d94078ee94b3c9e6e4552ad84f78bad7f75f` собран из исходников
и запущен на macOS ARM64. Проверены обычный счётчик, его перезапуск с потерей
состояния и восстановление из файла. Два ML-пилота по 20 шагов прошли
последовательную проверку весов, momentum, ID шагов и прогресса данных.
Продемонстрирована доступность данных для расчёта задержек, времени
восстановления и потерь подтверждённых эффектов.

Восстановление обучения с журналом/replay, неопределённый исход обновления,
отказы обычных вычислительных задач, процессный baseline и основные серии
измерений ещё не реализованы. Эти результаты не требуются в полном объёме
к КТ1 и входят в дальнейший объём проекта.

### 3. Минимальное распределённое обучение

```bash
python -m ray_ps.pilot --steps 20 --workers 2 --batch-size 32 --output runs/review-ps-01
python -m ray_ps.verify --run-dir runs/review-ps-01
python -m ray_ps.pilot --steps 20 --workers 2 --batch-size 32 --output runs/review-ps-02
python -m ray_ps.verify --run-dir runs/review-ps-02
```

Ожидание: три отдельных актора и обычные вычислительные задачи выполняют
20 шагов/40 расчётов градиента; каждый источник продвигается на 640 примеров;
веса и momentum совпадают с последовательным эталоном в заданном допуске.

Получено в обоих запусках:

- 20 шагов, 40 вычислений, позиции обоих источников — 640;
- все ID/версии/батчи прошли проверку, пропусков и дублей шагов нет;
- максимальная абсолютная ошибка весов — `5.960464477539063e-08`;
- максимальная абсолютная ошибка momentum — `5.960464477539062e-07`;
- сравнение прошло с `atol=1e-6`, `rtol=1e-5`;
- loss первого батчевого шага около 2.36, последнего — 1.42;
  это вспомогательная характеристика, не оценка качества на test set.

в данной среде; изменение одного элемента momentum на 1 обнаруживается;
пропущенный/повторный шаг или неверный батч отвергается.

Получено: контрольные суммы весов и momentum двух запусков совпали.
Изменённая копия состояния отвергнута, прежний `passed` в её отчёте заменён
на `failed`; оригиналы не изменены.
[Отчёт проверки](../evidence/kt1/pilot-checks.json).
Шесть unit tests прошли: три проверки файлового checkpoint и три проверки
манифеста/перехода эпох. [Вывод тестов](../evidence/kt1/unit-tests.txt).

### 5. Доступность данных основных метрик

```bash
python -m examples.recovery_probe --mode restart --output runs/review-probe-restart.json
python -m examples.recovery_probe --mode checkpoint --output runs/review-probe-checkpoint.json
```

Ожидание: журнал содержит ID операций/попыток, времена отправления и ответа,
запроса сбоя, готовности и первой полезной операции, PID и состояния.
По ним можно вычислить длительность восстановления, p95/p99 и потери.

Получено для 8 операций до и 8 после сбоя:

| Показатель | Restart | Файловый checkpoint |
| --- | ---: | ---: |
| Итоговое значение | 8 | 16 |
| Подтверждённые эффекты, потерянные в состоянии | 8 | 0 |
| От запроса сбоя до первого подтверждения после рестарта, мс | 1985.60 | 1986.82 |
| p95 increment, мс | 0.375 | 1.884 |
| p99 increment, мс | 0.400 | 2.720 |

Сырые события: [restart](../evidence/kt1/recovery-probe-restart.json)
и [checkpoint](../evidence/kt1/recovery-probe-checkpoint.json).
Каждая изменяющая операция имеет одну попытку, поэтому повторных increment
в этих проверках ноль; это не проверка повторов при неопределённом ответе.
Реальный учёт повторных gradient attempts и replay будет добавлен вместе
с отказами обучения.

ML-пилот также содержит времена каждого шага. В первом запуске p95/p99
равны 97.67/1437.64 мс, во втором — 84.75/1246.37 мс. В эти 20 шагов включён
дорогой первый запуск вычислительных процессов. Данные показывают возможность
расчёта квантилей; они не являются сравнением производительности или устойчивой
оценкой p99. Правило прогрева и размер основной выборки заданы
в [плане эксперимента](../experiment-plan.md).

## Ресурсы

Доступны 12 ядер и 36 ГиБ RAM на одной macOS ARM64-машине. Пилот работает
локально на CPU и завершился без исчерпания памяти. MNIST и маленькая ConvNet
не требуют GPU. Планируемые 2/4 вычислителя укладываются в число ядер;
перед основной серией замерим пиковую память процессов и уточним бюджет
8–16 ГБ для эксперимента. Сборка Ray требует дополнительных временных
ресурсов и отделяется от запуска измерений. [Полная среда](../environment.md).

## Ответственность участников

Для выбора предлагаются три основных направления. Каждый участник выбирает
направление и конкретный результат к КТ1; имена пока не назначены.
Задачи можно перераспределить по договорённости. Состав состояния, формат
событий и точки подтверждения нужно согласовать вместе, поскольку они
связывают все три направления.

| Направление | За какой вопрос отвечает | Дальнейший результат проекта |
| --- | --- | --- |
| A. Приложение и проверка правильности | Правильно ли выполняется обучение и как обнаружить ошибку? | Понятная модель состояния, воспроизводимые входы, эталон и проверки пропусков/дублей/неверного состояния |
| B. Восстановление и управляемые сбои | Как продолжить работу после смерти задачи или актора? | Checkpoint, журнал, replay, обработка повторных запросов и сценарии отказов |
| C. Baseline и измерения | С чем сравниваем и как считаем результат? | Вариант на обычных процессах, сбор/обработка метрик и воспроизводимые серии |
