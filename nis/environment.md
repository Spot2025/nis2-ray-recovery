# Среда учебных примеров

- Дата подготовки: 22.10.2026.
- Машина проверки: macOS 15.7.9, arm64.
- Python: 3.12.11, отдельное окружение `.venv/`.
- Ray: 2.59.0 из PyPI.
- Зависимости: `requirements.txt`.
- Фактическую ревизию установленного Ray программа записывает в JSON результата.

## Основная ревизия из задания

В [карточке задания](https://distsys.ru/osukhoroslov/nis2/src/branch/main/project-tasks/p25-b-ray-actors-recovery.md)
закреплён Ray `2ff4d94078ee94b3c9e6e4552ad84f78bad7f75f`.
В `_version.py` этой ревизии указана версия `3.0.0.dev0`.

По [официальной инструкции установки конкретного коммита](https://docs.ray.io/en/latest/ray-overview/installation.html#installing-from-a-specific-commit)
проверен адрес:

```text
https://s3-us-west-2.amazonaws.com/ray-wheels/master/2ff4d94078ee94b3c9e6e4552ad84f78bad7f75f/ray-3.0.0.dev0-cp312-cp312-macosx_12_0_arm64.whl
```

Команда проверки:

```bash
curl -I --fail --max-time 25 https://s3-us-west-2.amazonaws.com/ray-wheels/master/2ff4d94078ee94b3c9e6e4552ad84f78bad7f75f/ray-3.0.0.dev0-cp312-cp312-macosx_12_0_arm64.whl
```

Полученный ответ: **HTTP 404 Not Found**. Это свидетельство отсутствия сборки
по данному адресу, а не доказательство невозможности работы указанной ревизии.

Для учебных примеров использован доступный релиз 2.59.0. Сохранённые результаты
получены на этой версии; запуск основной ревизии задания не проверен.

## Границы результатов

Все три примера используют одного обычного синхронного актора и одного клиента.
`counter.py` проверяет работу без сбоев. `counter_restart.py` проверяет
падение процесса через `os._exit(1)` и один автоматический перезапуск:
состояние в памяти теряется, новый процесс начинает со значения 0.

`counter_checkpoint.py` добавляет сохранение в локальный JSON-файл после
каждого прибавления, до возврата ответа, и загрузку файла в конструкторе.
Два запуска подтвердили восстановление 50 и 7 соответственно, с итогами
100 и 10 после продолжения работы. Временный файл записывается и синхронизируется
через `flush`/`fsync`, затем атомарно заменяет основной checkpoint.

Проверена гибель процесса на той же машине при сохранении доступа к файлу.
Для рестарта на другом узле требуется доступное ему хранилище. Сбой питания,
утрата диска и гарантия сохранности метаданных файловой системы после сбоя
машины не исследовались. Вызов `fsync` каталога в примере не выполняется.

Падение происходит после получения всех ответов на первую группу операций.
Потеря ответов, неопределённый результат операции и повторная обработка
изменяющих состояние команд здесь не проверяются. Повторы разрешены только
для чтения состояния в период перезапуска, ожидание ограничено 60 секундами.

Если процесс погибнет после записи, но до доставки ответа, операция может быть
в checkpoint без подтверждения клиенту. В примерах нет идентификаторов запросов
и устранения повторов; гарантия exactly-once не заявляется.

Проверки не включают падение узла или всего кластера, пользовательский журнал
операций, replay после периодического checkpoint, процессный baseline
и измерение p95/p99. Запись checkpoint после каждой операции добавляет файловый
ввод-вывод; её влияние на производительность здесь не измеряется.
