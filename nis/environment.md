# Среда и воспроизводимость

## Основная среда КТ1

Проверено 22.10.2026 на macOS 15.7.9 / arm64:

| Компонент | Значение |
| --- | --- |
| Python | 3.12.11 |
| Ray | 3.0.0.dev0, нативная сборка |
| Назначенный и фактический SHA | `2ff4d94078ee94b3c9e6e4552ad84f78bad7f75f` |
| PyTorch / torchvision | 2.14.1 / 0.29.1 |
| NumPy | 2.5.4 |
| Доступная машина | 12 ядер, 36 ГиБ RAM; это полные ресурсы, не свободная память |
| Пилот | CPU, один поток PyTorch на процесс, 2 вычислителя, 2 источника, сервер модели |
| Окружение | `work/venvs/ray-pinned/`, отдельно от учебной `.venv/` |

На назначенной ревизии выполнены три счётчика, два запуска обучения по
20 шагов с последовательной проверкой, пробы восстановления и unit tests.
[Результаты и команды КТ1](checkpoints/01.md).

Для подготовки с нуля нужны Python 3.12 и Xcode Command Line Tools.
См. [инструкцию нативной сборки](build-ray-macos.md) и
[скрипт](../scripts/build_ray_macos.sh). Wheel хранится локально
в `work/build/wheels/` и не включён в Git. Linux-VM не использовалась.

После сборки и установки Ray:

```bash
source work/venvs/ray-pinned/bin/activate
python -m pip install -r requirements-pilot-deps.txt
python -m pip check
python -c 'import ray; print(ray.__version__, ray.__commit__)'
```

Все команды выполняются в корне репозитория. `requirements-pilot-deps.txt`
фиксирует зависимости пилота, исключая Ray, устанавливаемый из wheel.
`requirements-ml.txt` содержит только прямые ML-зависимости; для
воспроизводимости КТ1 используйте полный список зависимостей пилота.
Корневой `requirements.txt` сохраняет исторический Ray 2.59.0;
не устанавливайте его поверх среды с назначенным SHA.

Сборка прошла с Bazel 7.5.0 и Apple clang 17.0.0. Из-за ограничения
Java/Bazel сборочное дерево и кэш размещены по ASCII-пути. Штатно заполнен
placeholder ревизии в `_version.py`; исправлений runtime-кода Ray не было.
Не собирались отдельный необязательный C++ API, Redis для upstream-тестов
и frontend dashboard. Примеры используют Core с `include_dashboard=False`.

Пилот обучения не реализует восстановление модели, replay и процессный
baseline. Два одинаковых запуска подтверждают повторяемость данной
конфигурации в данной среде. Численные результаты на других платформах
и итоговая производительность систем по этим коротким опытам не установлены.

## Границы результатов счётчиков

Все три примера используют одного обычного синхронного актора и одного клиента.
`counter.py` проверяет работу без сбоев. `counter_restart.py` проверяет
падение процесса через `os._exit(1)` и один автоматический перезапуск:
состояние в памяти теряется, новый процесс начинает со значения 0.

`counter_checkpoint.py` добавляет сохранение в локальный JSON-файл после
каждого прибавления, до возврата ответа, и загрузку файла в конструкторе.
Два запуска подтвердили восстановление 50 и 7 соответственно, с итогами
100 и 10 после продолжения работы. Временный файл записывается и синхронизируется
через `flush`/`fsync`, затем атомарно заменяет основной checkpoint.

Проверена гибель процесса на той же машине при сохранении доступа к файлу.
Для рестарта на другом узле требуется доступное ему хранилище. Сбой питания,
утрата диска и гарантия сохранности метаданных файловой системы после сбоя
машины не исследовались. Вызов `fsync` каталога в примере не выполняется.

Падение происходит после получения всех ответов на первую группу операций.
Потеря ответов, неопределённый результат операции и повторная обработка
изменяющих состояние команд здесь не проверяются. Повторы разрешены только
для чтения состояния в период перезапуска, ожидание ограничено 60 секундами.

Если процесс погибнет после записи, но до доставки ответа, операция может быть
в checkpoint без подтверждения клиенту. В примерах нет идентификаторов запросов
и устранения повторов; гарантия exactly-once не заявляется.

Три исходных примера не включают падение узла или всего кластера,
пользовательский replay и процессный baseline. Отдельный `recovery_probe`
добавляет журнал и пробный расчёт p95/p99 и времени восстановления.
Этого короткого замера недостаточно для вывода о стоимости записи checkpoint.
