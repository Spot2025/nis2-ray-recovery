## Счётчик без сбоев

```bash
python examples/counter.py --output nis/evidence/counter.json
```

Ожидалось: начальное значение 0, результаты операций от 1 до 100,
итоговое значение 100, отдельный процесс актора.

Получено: все проверки пройдены. Среда и результат сохранены в
[`evidence/counter.json`](evidence/counter.json).

## Перезапуск без сохранения состояния

Команды выполнены 22.10.2026 в окружении Python 3.12.11 / Ray 2.59.0:

```bash
python examples/counter_restart.py --output nis/evidence/counter-restart.json
python examples/counter_restart.py --before-crash 7 --after-restart 3 --output nis/evidence/counter-restart-7-3.json
```

Перед сбоем клиент получает ответы на все операции первой группы.
Метод `crash()` завершает процесс актора через `os._exit(1)`.
При `max_restarts=1` Ray запускает новый процесс с тем же handle;
конструктор устанавливает счётчик в 0. Повтор команды падения отключён.

| Проверка | 50 до / 50 после | 7 до / 3 после |
| --- | ---: | ---: |
| Состояние до сбоя | 50 | 7 |
| Состояние сразу после перезапуска | 0 | 0 |
| Итог после второй группы операций | 50 | 3 |
| Всего подтверждено прибавлений | 100 | 10 |
| Подтверждённых прибавлений потеряно в состоянии | 50 | 7 |
| PID до → после | 9067 → 9070 | 9517 → 9520 |

В обоих запусках получен `ActorUnavailableError` при ожидании ответа `crash()`.
Все проверки пройдены: ответы первой и второй групп соответствуют
последовательностям от 1 до размера группы; процесс сменился, состояние
сбросилось. `status: passed` обозначает подтверждение этого поведения.

Этот сценарий показывает потерю состояния в памяти при автоматическом
перезапуске. Сбой происходит между группами подтверждённых операций;
вызовы с неизвестным клиенту результатом здесь не исследуются.
JSON сохраняется клиентом после эксперимента и не используется для восстановления.
